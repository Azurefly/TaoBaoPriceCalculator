# 店铺与组合优惠、本人浏览器购物车导入

## 当前连接方式：本人浏览器操作

首页 → 从淘宝购物车导入 → 打开浏览器登录淘宝 → 本人扫码 → 我已登录，读取商品 → 选择分组 → 导入选中商品。
首次仅需确认允许读取自己的购物车，取消不会发起连接；不需申请淘宝开发者账号、OAuth、API Key、
许可引用或复制 Cookie。旧 `TAOBAO_PLATFORM_PERMISSION_REFERENCE` 环境变量不再作为程序开关。
程序不将本机用户确认描述成平台授权；使用浏览器仍需遵守适用的账号、网站和数据使用规则。

技术路径为 Playwright 驱动本机可见 Chrome/Edge，读取已经渲染的页面元素，通过元素点击切换已识别
的淘宝购物车分组。不调用私有数据接口，不伪装人工、不绕过验证码。找不到已安装浏览器时尝试
Playwright Chromium；都不可用时明确提示。登录资料仅留在本机独立 `browser-profile`，不接管日常
浏览器默认资料，不导出或上传 Cookie。本工具不接收淘宝密码，不创建订单、支付或退款。

断开或手动关闭浏览器会撤销本次本机确认。重新连接不会自动开始批量操作。验证码、登录失效或
跳到非淘宝/天猫页面时停止。分组切换前及自动勾选、进入结算前重新检查页面，不强行点击遮挡元素。

普通用户只需使用购物车导入入口。高级接口中的 `permitted()` / `require_permission()` 兼容名称现在
只表示本机用户确认，绝不代表平台授权。高级结算试算仍需校准商品行、数量、全量标记及“结算”按钮，
且需单独开启，不会因用户打开浏览器而自动启动。

## 分组与数据范围

淘宝原生分组、按店铺筛选和当前页面三个来源分别标识。只有具有明确原生分组ID及标签的页面才
自动点击分组；不按名称猜测。标签切换后还要等商品行实际改变并稳定，不能把旧组数据贴上新组名称。
切组失败时前后端都清除旧快照，不能改为导入全部商品；无法识别原生分组时，由本人在网页切换后
读取当前页面。App独有、网页不展示的分组无法凭空读取。

只读取当前加载行，尚未覆盖所有分页和虚拟滚动；每次查看最多500行，单次优化计划最多28行。
重复标识、未知数量、失效行、快照过期或账号/清单版本冲突会停止，不悄悄截断或合并。换账号先
断开，再勾选“这次换了淘宝账号”；暂不自动验证淘宝登录主体。同来源行可幂等导入；数量变化后
必须重新核价，不覆盖已付款商品。

## 已支持的优惠表达

店铺/指定商品/排除商品；凑门槛与获得优惠的商品可以不同；必买搭配数量、满件、不同SKU数；
固定满减、每满减、折扣封顶、多档满减、明确数量的套餐一口价；同组自动择优、整笔或重叠商品互斥；
规则顺序、门槛基数、入口和有效期分别配置。物理券余额跨笔共用，耗尽后的替代优惠进入顺序搜索。
每笔输出采用的优惠及分摊明细。候选与余额情景有预算上限，截断要明示。

这并非对全部淘宝活动的自动识别。只看到“满X减Y”不能推断全部适用商品、叠加或领券资格。
券后展示价不倒推原价，也不再次扣券；购物车金额保持待核对，真实报价以结算页面和权益消耗为准。
本次连接修改没有改变优惠数学、解决全部页面适配或实现私人券包的自动读取。

## 简单测试与限制

右上角“一键体验”自动准备虚构购物车、分组和组合优惠；不连接淘宝、不改真实清单。体验中不允许
连接真实账号或把示例导入真实清单。真实账号页面、全量个人券包、所有直播间/App权益、数量自动拆单、
未核实退款收益仍未完成。当前连接流程已用模拟浏览器和合成界面测试，尚未做真实淘宝账号端到端验收。
Mac 签名及公证状态不因本次改动改变。
